# Agent A 產品評審：drawing_note_enhance_v2

評審日期：2026-06-20  
範圍：只評審現有繪圖記事的使用者體驗；本文件不要求本輪修改 App 程式碼。

## 一句話結論

第一版繪圖記事已經把「不誤留空白草稿、可復原清除、儲存可信、PNG 分享／匯出不重複觸發」補起來，基礎安全感是好的。v2 不應該追更多畫筆功能；最高槓桿是讓繪圖記事在首頁一眼被認出，並讓新繪圖的第一秒更像一張紙，而不是一個顯示「未命名／已儲存」的表單。

## 查核依據

- `DrawingEditorScreen`、工具列、畫布、PNG 分享／匯出：`app/src/main/java/com/example/notepad/ui/NotepadApp.kt`
- 首頁卡片與標題規則：`NoteRow`、`noteTitle`
- 提醒與 Premium gate：`ReminderControls`
- 現有繪圖測試：`app/src/androidTest/java/com/example/notepad/TextInputTest.kt`
- 既有繪圖工作紀錄：`Doc/jobs_view/drawing_note/`
- 舊版畫面圖：`Doc/ui_design_v1.2.0_current/06_drawing_handwriting/`，僅作歷史參考；目前程式碼已不是舊的文字 pill 工具列。

## 現況評審

### 1. 建立與空白畫布

目前新增繪圖記事後，空白且沒有標題時會自動進入全螢幕繪圖模式。這個方向正確：使用者點「新增繪圖記事」後，第一件事應該是畫，而不是填表。

問題是空白狀態仍顯示「未命名繪圖」與儲存狀態。對一張還沒有任何筆畫、離開時可能會被丟棄的草稿來說，「已儲存」不是使用者真正需要知道的訊號。它讓第一秒像資料庫記錄，而不是紙。

### 2. 工具

目前工具列已比舊版好很多：undo/redo/clear/share/export 是 icon，清除有確認，筆／橡皮擦、粗細、顏色都有 48dp 觸控目標與語意標籤。這是可接受的 v1 基準。

仍有小螢幕問題：第二列工具是水平捲動，筆、橡皮擦、三個粗細、四個顏色放在同一排，360dp 手機上顏色不會全露出。這不是阻塞，但代表 v2 不應再新增更多常駐工具。

### 3. 標題

標題只在一般模式出現，全螢幕先讓使用者畫，方向正確。問題在首頁：有筆畫但沒有標題的繪圖都叫「未命名繪圖」。繪圖是視覺記憶，卻在列表中被降級成一行文字。這會讓多張草圖彼此不可分辨。

### 4. 儲存與返回

目前有繪圖儲存狀態、失敗重試、返回前儲存、失敗時不離開、空白新草稿離開時硬刪且不進垃圾桶。這是可靠的。

返回行為目前是：全螢幕按系統 Back 先離開全螢幕，再按一次才回列表或丟棄空白草稿。這保守且安全。文案上，一般模式 top bar 仍是「返回」而非「完成」，但 v2 不必為了這個單點重做流程；它應跟空白畫布 chrome 一起處理。

### 5. 分享／匯出

PNG 分享／匯出目前會先儲存再產生 PNG，進行中會停用按鈕，失敗會停住並顯示狀態，這是對的。問題是自然的繪圖模式是全螢幕，但全螢幕完全不顯示分享／匯出。使用者必須先知道要按「完成／離開全螢幕」才會看到檔案動作。

這不是資料風險，是發現性風險：畫完想立刻傳給別人，找不到。

### 6. Premium 提醒互動

提醒／日曆仍是 Premium。繪圖一般模式會顯示提醒控制；免費使用者點設定提醒會先保存或丟棄空白草稿，再進 Premium。這個資料安全邏輯是對的。

對產品感受來說，新增繪圖一開始不顯示提醒與資料夾是好的，不會在創作第一秒推 Premium。v2 應維持：Premium 提醒可以在「詳細資料／更多」裡出現，不要常駐壓在空白畫布上。

### 7. 小螢幕可用性

全螢幕模式是目前最適合小手機的主流程。一般模式同時有標題、狀態、資料夾、提醒、畫布、工具列，畫布容易被壓縮；因此 v2 應把一般模式定位成「詳細資料與檔案動作」，不是主要繪圖面。

## v2 優先順序

### P0：首頁加入繪圖縮圖，讓繪圖記事有視覺記憶

**產品判斷**  
繪圖記事如果在首頁只是一張文字卡，就不像繪圖記事。這是目前最大品味缺口，也是最能讓使用者覺得功能變完整的改善。

**建議行為**  
有筆畫的繪圖記事，在首頁、搜尋結果、提醒日曆清單等所有使用 `NoteRow` 的列表中，顯示一個小型固定高度縮圖。縮圖只做辨識，不可互動。沒有標題也沒關係，縮圖就是它的名字。

**實作邊界給後續 Agent**

- 不新增資料表、不儲存縮圖檔、不做背景產圖。
- 直接解碼 `note.drawingData`，用現有 Compose 繪圖 renderer 或抽出小型共用 renderer。
- 縮圖高度固定，建議約 72-96dp；白底、細邊界、8dp 以內圓角，放在卡片標題／預覽區下方。
- eraser stroke 必須和編輯器／PNG 匯出一致。
- 空白但被刻意保留的繪圖可顯示安靜的「空白繪圖」或空白預覽，不可顯示 raw JSON。
- 不要改 `noteTitle` 儲存語意；未命名繪圖仍可叫「未命名繪圖」，但列表必須靠縮圖區分。

**驗收標準**

- 建立一張有筆畫但無標題的繪圖，返回首頁後卡片顯示 `drawing_note_thumbnail_<id>`，且仍可點卡片開啟原繪圖。
- 建立兩張不同筆畫、皆無標題的繪圖，首頁視覺上可分辨，不只是一串相同的「未命名繪圖」。
- 搜尋／篩選到繪圖記事時，縮圖仍顯示；垃圾桶中如顯示該 note row，也不破版。
- 縮圖不顯示 raw drawing JSON，不改變分享／匯出檔名規則。
- 含橡皮擦的筆畫在縮圖中與編輯器視覺一致。
- 360dp 寬螢幕截圖中，縮圖不擠壓標題、時間、提醒摘要或更多選單。

### P1：把「第一張紙」做乾淨，並在全螢幕提供一個明確的更多入口

**產品判斷**  
新增繪圖後，使用者應該感覺自己拿到一張紙。現在第一秒仍有「未命名繪圖」和「已儲存」這種資料庫感。另一方面，使用者畫完想分享或命名時，必須猜到要先離開全螢幕。

**建議行為**

- 對全新的空白繪圖草稿，在尚未畫筆畫、尚未輸入標題、尚未改資料夾／提醒前，不顯示「未命名繪圖」與「已儲存」。
- 保留明確的離開全螢幕控制；標籤使用「完成」或「返回詳細資料」，不要用泛用的「專注／書寫」語意。
- 全螢幕右上或底部工具列提供一個 More／Details 入口，打開後可看到：標題、資料夾、提醒、分享 PNG、匯出 PNG。這些不應常駐壓在畫布上。
- 使用者畫第一筆後，可以顯示簡短儲存狀態；但仍不要把空白標題強行變成主要視覺。
- 免費使用者在 Details 裡點提醒，沿用現有 Premium gate；不得因進 Premium 留下一張空白草稿。

**驗收標準**

- 新增繪圖記事後的初始全螢幕，沒有「未命名繪圖」、沒有「已儲存」或「剛剛已儲存」文字；畫布與畫筆工具是主要視覺。
- 空白新繪圖按系統 Back 離開全螢幕，再離開編輯器後，不會在首頁或垃圾桶留下草稿。
- 畫第一筆後，儲存狀態可見且會正常進入「儲存中／剛剛已儲存」；儲存失敗時必須顯示錯誤與重試，不可為了乾淨畫面隱藏失敗。
- 全螢幕 More／Details 入口在 360dp 寬螢幕可點擊且不遮住畫布筆跡。
- 從全螢幕 More／Details 分享或匯出 PNG，會先保存最新筆畫，進行中停用重複點擊，結果與一般模式分享／匯出一致。
- 免費使用者從全螢幕 Details 點提醒進 Premium，空白草稿不殘留；已有筆畫或標題的草稿保留。

## 明確不建議 v2 做

- 不要在 v2 追加形狀、文字框、圖層、套索、筆跡美化等重工具。
- 不要改 drawing JSON 格式或做 schema migration。
- 不要把提醒改成免費功能；Premium gate 只要更不打擾即可。
- 不要在 v2 改成全套縮放／平移／固定頁面模型。現有畫布會自動縮放超出邊界的內容，這確實是長期產品債，但牽涉座標、匯出尺寸、手勢與既有測試，應另開 v3 設計決策。

## Agent B 起手建議

先規劃 P0，再評估 P1 是否能在同一版完成。若時間有限，只做 P0；它最直接改善使用者每天在首頁找圖的體驗。P1 可以分成兩步：先隱藏空白草稿的「未命名／已儲存」chrome，再加入全螢幕 More／Details。
