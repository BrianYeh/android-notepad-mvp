# Just Notes v2 / v3 手動測試說明 - 2026-06-20

這份說明是給 Google Drive 測試資料夾裡的 debug APK 使用：

`G:\我的雲端硬碟\01_android_app\01_note_app\app-debug.apk`

目前這版 APK 包含兩輪文字筆記改進：

- v2：讓新增文字筆記、閱讀頁、首頁卡片更乾淨、更直接。
- v3：空白筆記以正文輸入為優先、閱讀模式可點擊進入編輯、支援混合 markdown checkbox 顯示，並修正 checkbox / 格式穩定性問題。

## 測試前

- 請安裝或更新同一個 Google Drive 資料夾裡的 `app-debug.apk`。
- 建議用幾則既有筆記測試，再另外新增幾則新筆記。
- 如果遇到不對勁的地方，請記錄所在畫面、操作動作，以及當時是在編輯模式、閱讀模式、首頁列表、搜尋、垃圾桶、提醒或月曆畫面。

## v2 改進測試項目

### 1. 首頁主要新增按鈕會直接建立文字筆記

- 在首頁點主要新增按鈕。
- 預期：立刻開啟一則新的文字筆記。
- 預期：游標 / 焦點直接在正文輸入區，可以馬上打字。
- 打開次要新增 / 選項按鈕。
- 預期：其他建立類型仍然在這裡，例如 checklist、繪圖、OCR、資料夾。

### 2. 文字筆記閱讀頁更乾淨

- 新增並儲存一則一般文字筆記。
- 從首頁列表打開它。
- 預期：閱讀頁主要呈現標題和正文內容。
- 預期：一般 metadata 不會擠在主閱讀頁上，例如資料夾、更新時間、正常已儲存狀態、沒有提醒狀態、釘選狀態。
- 打開筆記右上角選單，選 Details。
- 預期：那些一般 metadata 可以在 Details 裡看到。
- 建立或打開一則有提醒的筆記。
- 預期：提醒資訊仍然會出現在需要看得到的地方。
- 如果方便，可以模擬儲存失敗狀態。
- 預期：儲存失敗狀態仍然會清楚顯示，而且可以操作。

### 3. 首頁筆記卡片更乾淨

- 在首頁列表檢查文字筆記卡片。
- 預期：卡片顯示標題、短正文預覽、相對更新時間。
- 預期：釘選、移動、刪除、還原、永久刪除這類操作放在卡片選單裡，不會擠在卡片上。
- 到垃圾桶打開卡片選單。
- 預期：可以看到還原和永久刪除。
- 用搜尋找筆記正文裡的字。
- 預期：搜尋結果預覽仍然會顯示有用的正文上下文和標示。
- 如果有啟用隱私鎖，確認卡片選單不會洩漏被鎖住時不該出現的操作。

## v3 改進測試項目

### 4. 空白文字草稿以正文優先

- 新增一則一般文字筆記。
- 預期：正文輸入區立刻取得焦點。
- 預期：草稿完全空白時，精簡狀態 / metadata 列會隱藏。
- 預期：完整 metadata / details 卡片預設隱藏。
- 打開編輯模式選單，選 Details。
- 預期：標題和詳細資料仍然可以從這裡進入。
- 從月曆或提醒流程建立一則提醒型文字草稿。
- 預期：提醒型空白草稿仍然會顯示提醒 metadata；空白草稿隱藏規則不應該把提醒資訊藏掉。

### 5. 只有正文、沒有標題的筆記，會用第一行正文當顯示標題

- 建立一則沒有明確標題、只有正文的筆記，例如：

```text
購物想法
牛奶
雞蛋
```

- 儲存並回到首頁列表。
- 預期：筆記可以用第一個非空白正文行作為顯示標題 / 名稱。
- 重新打開筆記。
- 預期：實際儲存的標題可以維持空白，但畫面上會用正文第一行顯示。

### 6. 閱讀模式點擊即可編輯

- 打開一則既有文字筆記，停在閱讀模式。
- 點可見標題。
- 預期：進入標題 / 詳細資料編輯。
- 點一般正文文字，不要點連結。
- 預期：進入正文編輯，而且游標位置接近剛才點的位置。
- 點明確的 Edit 按鈕。
- 預期：進入正文編輯。
- 加入一個網址，例如 `https://example.com`，儲存後在閱讀模式點網址。
- 預期：網址優先，app 會嘗試開啟連結，而不是立刻進入編輯。
- 點網址旁邊的一般文字。
- 預期：一般文字仍然會進入正文編輯。

### 7. 筆記內搜尋仍然正常

- 在閱讀模式開啟 Find，搜尋筆記正文裡的文字。
- 預期：可以找到匹配項目，閱讀視窗會在需要時捲動。
- 進入編輯模式後再使用 Find。
- 預期：編輯模式下也可以繼續切換搜尋結果。

### 8. 混合 markdown checkbox 顯示

- 建立一則混合內容的文字筆記：

```text
專案清單

- [ ] 第一個任務
一般段落，包含 https://example.com
- [x] 已完成任務
- [X] 大寫 X 的已完成任務

結尾文字
```

- 儲存後用閱讀模式打開。
- 預期：checkbox 行會顯示成可點擊的 checkbox row。
- 預期：一般文字、空白行、網址、結尾文字仍然會正常顯示在 checkbox row 前後。
- 點未勾選的 checkbox。
- 預期：會變成已勾選，而且重新打開筆記後仍然保留。
- 點已勾選的 checkbox。
- 預期：會變成未勾選，而且重新打開筆記後仍然保留。
- 點 checkbox 的文字標籤，不要點方框。
- 預期：進入正文編輯，位置在該正文附近。
- 點網址。
- 預期：網址行為仍然優先，不會被誤判成進入編輯。

### 9. 勾選 checkbox 不應破壞既有格式或換行

- 如果你有一則既有的格式化筆記，裡面含有 markdown checkbox，請在閱讀模式切換 checkbox。
- 預期：其他文字周圍的格式保持穩定。
- 預期：內容不會突然黏在一起，也不會遺失空白行。
- 預期：使用 Windows 風格換行或混合換行的筆記，在切換 checkbox 後格式位置仍然穩定。

### 10. 返回鍵與保存

- 編輯一則筆記，然後點 app 內的返回按鈕。
- 預期：編輯內容會保存，app 乾淨回到上一層。
- 再次編輯，然後按 Android 系統 Back。
- 預期：編輯內容會保存，而且不會卡在編輯器狀態。
- 重新打開 app / 筆記。
- 預期：最新的標題、正文、checkbox 狀態、提醒資訊都正確。
