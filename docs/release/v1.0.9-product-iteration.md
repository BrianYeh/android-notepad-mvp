# Just Notes v1.0.9 Product Iteration

Status: regression, upgrade smoke, and final review passed; signed AAB pending
Target release: Google Play Production
Target markets: Taiwan, United States, Canada, United Kingdom, Australia, New Zealand, Singapore, Hong Kong

## Product promise

> Capture it now. Find it when it matters.

Just Notes v1.0.9 focuses on activation and repeat use rather than adding another
unrelated power feature. The product remains local-first, ad-free, and usable
without account sign-in.

## User-facing scope

### First-use experience

- A first-run welcome experience explains quick capture, useful retrieval, and
  local-first storage.
- A user can create the first note or open the template picker immediately.
- Skipping the welcome is persisted.
- Deleting every note later must show the normal starter state, not restart the
  first-run welcome.

### Built-in templates

The app includes localized, read-only starters that create ordinary notes:

- Daily checklist
- Shopping list
- Meeting or class notes
- Journal
- Trip preparation
- Important dates

Templates do not add a database entity or sync format. After creation, the
result is a normal text or checklist note that can be edited, backed up,
synced, exported, and deleted through the existing paths.

### Today

The Today destination is derived from existing active notes and shows:

1. overdue reminders;
2. reminders due today;
3. pinned notes not already shown;
4. recently updated notes not already shown.

It also offers quick actions for a text note, checklist, and reminder. The
classification uses the device's local day boundary and is covered by pure
tests.

### Search

- Search remains entirely on-device.
- Queries are not persisted or logged as analytics.
- Phrase matching remains supported.
- Normalized whitespace, diacritic-insensitive matching, and an all-token
  fallback make imperfect queries more useful.
- A zero-result state gives the user a clear recovery path.

### Measurement and privacy

The release does not add an analytics SDK, content telemetry, search-query
logging, or in-app usage counters. Product decisions use Google Play's
aggregate acquisition, conversion, stability, and retention reports. Notes,
folders, drawings, checklist items, reminders, and search queries are not sent
as product analytics.

## Post-publication learning plan

Observe the eight production markets for 2–4 weeks without changing the
subscription products:

- store-listing visitors to first-time installers, split by locale and country;
- acquisition source and store-listing conversion;
- daily and 28-day returning users from Google Play's aggregate reports;
- crash-free and ANR-free user rates;
- subscription purchase, cancellation, and renewal outcomes already provided
  by Google Play and the existing billing backend.

The hypotheses are:

1. a clearer local-first promise and authentic screenshot story improve store
   conversion;
2. the welcome, starter hub, and templates reduce first-use uncertainty;
3. Today and more forgiving search improve repeat usefulness.

Do not infer success from installs alone. A rollout is healthy only when
conversion or returning use improves without a regression in stability,
uninstalls, billing correctness, or user feedback. No note-content analytics or
new tracking SDK is required for this evaluation.

## Deliberately out of scope

- Custom or synced template entities
- Room schema changes
- Backup or sync format changes
- Collaboration or a web editor
- Cloud generative AI
- Billing product, price, trial, purchase-orchestration, or RTDN changes
- Cloud Run, IAM, KMS, Secret Manager, or Firestore changes

## Privacy and Play claims

Approved positioning:

- "Notes stay on-device by default."
- "Google Drive sync is optional."
- "On-device OCR."
- "No advertising."

Disallowed claims:

- end-to-end encrypted or zero-knowledge;
- guaranteed reminder delivery;
- guaranteed search speed;
- an unconditional 10-day trial;
- fixed subscription prices in screenshots.

## Quality gate

The release cannot be called PASS until all of the following are proven from a
clean candidate:

- debug and release JVM unit tests;
- backend tests;
- debug lint and release vital lint with no blocking errors, with warnings
  reviewed against the migration baseline;
- debug, release, androidTest, and signed bundle builds;
- compliance-site verification;
- API 36 connected tests in four sequential shards;
- exact XML test union with no missing, duplicate, failed, errored, skipped, or
  aborted test;
- no app ANR, process crash, input timeout, emulator-offline, package-service,
  or instrumentation-abort hazard;
- gesture and 3-button navigation functional smoke;
- edge-to-edge, IME, cutout, predictive-back, search, selection, dialogs, and
  editor-save smoke;
- v1.0.8 to v1.0.9 upgrade smoke preserving notes, folders, reminders, and
  entitlement state;
- independent xhigh review with every actionable finding resolved.

The release connected baseline runs on the API 36 Play Store emulator in four
sequential shards. API 35 results are retained below as historical migration
evidence but are no longer a development or release gate. When an isolated test
fails, the root cause is still investigated and fixed, but a focused API 36
retest of that test and its directly affected behavior is sufficient; the
entire shard does not need to be repeated.
