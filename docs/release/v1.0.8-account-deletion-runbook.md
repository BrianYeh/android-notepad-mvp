# Just Notes v1.0.8 Account-Deletion Runbook

Updated: 2026-07-12

This runbook covers authenticated deletion of eligible Just Notes backend account data. Never paste or record a Google ID token, email address, Google subject, purchase token, token hash, ciphertext, reviewer credential, or Firestore document contents in a ticket, terminal transcript, screenshot, or log.

## User prerequisites

1. The user cancels any active Just Notes subscription in Google Play.
2. The subscription reaches a terminal `Expired` or `Revoked` state. Cancellation alone can leave Premium active until expiry.
3. The user understands that backend deletion does not remove local notes, a private Google Drive backup, the Google account, or Play billing history controlled by Google.
4. The user authenticates on the official account-deletion page and completes the explicit confirmation.

## HTTP outcomes

- `204 No Content`: eligible entitlement and owned terminal subscription documents were deleted atomically. Do not expect or record a response body.
- `409 Conflict`: at least one entitlement or subscription is nonterminal. Tell the user to cancel in Google Play, wait for expiry, refresh Just Notes, and retry.
- `401 Unauthorized`: authentication is missing or expired. Ask the user to authenticate again; never request that the token be sent to support.
- `400` or `403`: the request or origin is invalid. Confirm that the user is on the official GitHub Pages URL.
- `503 Service Unavailable`: deletion failed closed. Escalate using timestamps and fixed status codes only.

## Operational verification

1. Confirm the Cloud Run revision is healthy and no IAM or deployment change occurred during the request.
2. Verify only existence/count and terminal-state predicates for the account's entitlement and subscription records. Do not print document IDs, paths, field maps, hashes, encrypted values, or record contents.
3. After `204`, confirm the eligible entitlement record and owned terminal subscription records no longer exist using boolean/count-only output.
4. Do not delete RTDN deduplication records. Their Firestore TTL remains the retention authority and should stay active with the existing 30-day expiry behavior.
5. Scan Cloud Run logs for forbidden sensitive field names and value patterns. Record only a pass/fail count; do not copy a matching value into evidence.
6. Confirm retry and dead-letter subscriptions have no deletion-related abnormal accumulation.
