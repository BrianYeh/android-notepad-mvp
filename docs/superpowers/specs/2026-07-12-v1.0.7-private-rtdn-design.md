# Just Notes v1.0.7 Private RTDN Design

Status: approved 2026-07-12

## Goal

Process Google Play Real-time Developer Notifications without exposing an RTDN endpoint publicly and without breaking the existing Android billing API.

## Decision

Use two Cloud Run services built from the same reviewed backend image:

| Service | Invocation | RTDN flag | Responsibility |
|---|---|---|---|
| `just-notes-entitlement-api-dev` | `allUsers`; Ktor authenticates Android billing routes with Google ID tokens | `RTDN_ENABLED=false` | Existing Android health, billing context, verify, and entitlement API. `/v1/play/rtdn` remains `501`. |
| `just-notes-rtdn-dev` | Private Cloud Run IAM; only the dedicated Pub/Sub push identity has `roles/run.invoker` | `RTDN_ENABLED=true` | Authenticated Pub/Sub push processing. Other routes exist in the shared image but are unreachable without Cloud Run IAM. |

Cloud Run IAM is service-wide, not path-specific. Splitting services preserves the public Android API while giving the RTDN push endpoint a platform authentication boundary.

## Identities and permissions

- Runtime identity: reuse `just-notes-entitlement-api-dev@gen-lang-client-0599059254.iam.gserviceaccount.com` so RTDN has the already reviewed Firestore, KMS, Secret Manager, and Android Publisher permissions.
- Push identity: create `just-notes-rtdn-push-dev@gen-lang-client-0599059254.iam.gserviceaccount.com`.
- Grant the push identity only `roles/run.invoker` on `just-notes-rtdn-dev`.
- Grant the Google-managed Pub/Sub service agent `roles/iam.serviceAccountTokenCreator` on the push identity so Pub/Sub can mint the OIDC token.
- Never grant `allUsers` or `allAuthenticatedUsers` on `just-notes-rtdn-dev`.

## Delivery and data flow

1. Google Play publishes a `DeveloperNotification` to `just-notes-rtdn-dev` topic.
2. Pub/Sub pushes a wrapped message to the private Cloud Run service using an OIDC token whose audience is the private service origin.
3. Cloud Run IAM validates the token and invoker permission before Ktor receives the body.
4. Ktor validates strict body/data size limits, Pub/Sub subscription name, base64 encoding, package name, and supported subscription notification shape.
5. The backend hashes the Pub/Sub message ID and claims a Firestore processing lease. It never persists the body or token.
6. The notification purchase token is used only to compute the existing ownership-document hash. RTDN cannot create a first owner binding.
7. The backend loads the owner-bound subscription, decrypts its stored ciphertext with KMS, hashes the decrypted token again, and requires it to match the document key.
8. Android Publisher `subscriptionsv2.get` supplies authoritative lifecycle truth. The notification type is only a requery hint.
9. Existing monotonic subscription and entitlement reconciliation handles renewal, recovery, grace period, hold, pause, cancellation, expiry, refund/revocation, and linked replacements.
10. Successful/terminal-safe processing completes the event. Retryable KMS, Firestore, or Play failures release the lease and return `503` so Pub/Sub redelivers.

## Firestore event schema

Collection: `rtdnEvents/{sha256(messageId)}`.

Allowed fields:

- `generation`
- `leaseUntil`
- `retryAt`
- `completedAt`
- `outcome`
- `errorCode`
- `attemptCount`
- `expiresAt`

Forbidden fields include message body/data, purchase token or token hash, Google subject/email, bearer/OIDC token, ciphertext, and Android Publisher response.

`expiresAt` uses a 30-day Firestore TTL policy.

## Pub/Sub reliability

- Push subscription: `just-notes-rtdn-push-dev`.
- Retry backoff: 10 seconds minimum, 600 seconds maximum.
- Message retention: 7 days.
- Maximum delivery attempts: 10.
- Dead-letter topic: `just-notes-rtdn-dead-letter-dev`.
- A dead-letter pull subscription is retained for redacted operational inspection.
- Duplicate and out-of-order deliveries are expected and must be idempotent.

## HTTP behavior

- `204`: processed, already completed, or unsupported notification safely ignored.
- `400`: malformed/oversized envelope or package/subscription mismatch.
- `503`: retryable dependency failure or owner binding not available yet.
- `500`: unexpected redacted failure.
- Every response sets `Cache-Control: no-store`.
- The existing public service continues returning `501 {"error":"rtdn_not_enabled"}`.

## Deployment and rollback

1. Deploy a reviewed image to the new private service with RTDN enabled.
2. Verify unauthenticated calls receive platform `403`; authenticated operator health works.
3. Create Pub/Sub resources and publish synthetic test notifications before configuring Google Play.
4. Inspect Firestore event documents and logs for redaction/idempotency.
5. Configure the Play Console RTDN topic only after canary gates pass.
6. Validate a license-tester accelerated renewal/cancellation/expiry cycle.

Rollback never touches the stable Android API service. Remove the Play Console topic, disable or delete the push subscription, and deploy `RTDN_ENABLED=false` to the private service if processing fails.

## Verification gates

- Parser, dedupe concurrency, processor, route, and cross-layer acceptance tests pass.
- Full backend and Android suites, lint, debug build, Docker build, and secret scan pass.
- xhigh review has no unresolved P0/P1/P2 findings.
- Private service rejects unauthenticated calls and has no public invoker binding.
- Pub/Sub synthetic duplicate/retry/dead-letter behavior is verified.
- Real Play state changes are derived from Publisher responses, not payload notification type.
- Logs and Firestore contain none of the forbidden sensitive values.

## Alternatives rejected

- App-layer verification on the existing public service: workable, but adds JWT issuer/audience/email verification code and leaves the route internet-reachable before Ktor authentication.
- Making the existing service private: rejected because Android's Google ID token is not a Cloud Run IAM identity token and existing app calls would fail at the platform boundary.
- Shared secret header: rejected because it is weaker than Pub/Sub OIDC and creates another rotatable secret.
