# Just Notes v1.0.7 RTDN Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add authenticated, idempotent Google Play Real-time Developer Notifications that requery Play truth and reconcile renewal, cancellation, refund, revocation, expiry, grace-period, and account-hold changes without trusting notification state.

**Architecture:** A private Pub/Sub push subscription invokes the Cloud Run RTDN route with an OIDC token; Cloud Run IAM authenticates the dedicated push service account before Ktor receives the request. The backend validates and deduplicates the Pub/Sub envelope, uses the notification purchase token only to locate an already owner-bound encrypted subscription, decrypts the stored token with KMS, requeries Android Publisher, and runs the existing monotonic entitlement reconciliation. Firestore stores only redacted event state and existing ciphertext metadata; raw tokens and notification bodies are never persisted or logged.

**Tech Stack:** Kotlin/JVM 17, Ktor, Google Cloud Pub/Sub push, Cloud Run IAM/OIDC, Android Publisher `subscriptionsv2`, Firestore transactions/TTL, Cloud KMS, JUnit, Gradle 8.10.2.

## Global Constraints

- Keep `/v1/play/rtdn` returning `501` until every code, infrastructure, review, and canary gate in this plan passes.
- Accept only Pub/Sub push requests authenticated by Cloud Run IAM as the dedicated RTDN push service account; never make the route public.
- Treat the RTDN payload as a change hint only. Entitlement state comes exclusively from a fresh Android Publisher query.
- Do not create an owner binding from RTDN. A token must already exist in `subscriptions/{purchaseTokenHash}` with an owner established by authenticated app verification.
- Persist no raw purchase token, bearer/OIDC token, Google subject/email, ciphertext value, or full notification body in event documents or logs.
- Preserve the existing `v1.0.7` catalogue: package `com.brianyeh.justnotes`, product `just_notes_premium`, base plans `monthly` and `annual`, and optional monthly offer `trial10d`.
- Keep acknowledgement backend-only and preserve the existing monotonic successor/terminal-denial rules.
- Use a dedicated Pub/Sub dead-letter topic and retry policy; do not acknowledge retryable dependency failures as success.
