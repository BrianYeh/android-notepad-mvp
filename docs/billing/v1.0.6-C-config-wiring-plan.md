## 2. Android Wiring

The checked-in `gradle.properties` supplies the non-secret Web OAuth client ID
through `justNotes.googleWebClientId`.

`justNotes.backendBaseUrl` remains explicitly blank. This is intentional:

- no Cloud Run service has been deployed;
- there is no reviewed HTTPS backend origin to call;
- a blank endpoint keeps `HttpBackendEntitlementClient` disabled;
- configuring the Web client ID alone can request an ID token for the existing
  Google sign-in flow, but cannot make a backend entitlement request.

The Android Gradle script rejects a non-empty backend URL unless it is an HTTPS
origin without a path, embedded credentials, query, or fragment. It also rejects a
non-empty Web client ID unless it has the Google Web OAuth client ID form
`*.apps.googleusercontent.com`.

Runtime validation repeats the fail-closed checks before an ID token can be
sent over the network:

| Android configuration | Result |
| --- | --- |
| Blank backend URL | `BackendEntitlementFetchResult.Disabled` |
| HTTPS URL plus valid Web client ID | Eligible for `GET /v1/entitlement` after sign-in |
| HTTP, malformed, path-bearing, credential-bearing, query-bearing, or fragment-bearing URL | Failure before opening a connection |
| Non-empty backend URL plus missing or malformed Web client ID | Failure before opening a connection |
| Missing ID token | `NotSignedIn`; no entitlement is applied |

## 4. Current Non-Granting Boundary

The production module intentionally remains a skeleton:

- `NoopPlaySubscriptionVerifier` always fails;
- `InMemoryEntitlementRepository` is not a production Firestore authority;
- the KMS encryptor and Secret Manager provider are not implemented;
- `POST /v1/billing/verify` returns HTTP `202`, `hasPremium=false`,
  `VerificationPending`, and `POST_VERIFY_DISABLED`;
- RTDN returns `501 rtdn_not_enabled`;
- Android release entitlement remains backend-verified only;
- `justNotes.allowClientOnlyBillingEntitlement` remains `false` by default and
  is forced to `false` for release builds.

Config wiring must not be treated as authorization to replace any of these
boundaries.

## 5. Deferred Deployment Work

The following work requires a separate implementation and approval pass:

1. Implement an official `purchases.subscriptionsv2.get` verifier using the
   Cloud Run service account and Application Default Credentials.
2. Implement Secret Manager-backed versioned pepper providers.
3. Implement Cloud KMS encryption that stores `tokenCiphertext`, `keyVersion`,
   `encryptedAt`, and `encryptionAlgorithm` and never persists raw tokens.
4. Implement a Firestore repository with ownership and stale-entitlement
   protections.
5. Implement reliable backend acknowledgement and retry behavior.
6. Containerize and deploy the reviewed service to Cloud Run.
7. Capture the deployed HTTPS origin, set `justNotes.backendBaseUrl`, rebuild,
   and verify Google ID token audience handling end to end.
8. Only in the separately approved v1.0.7 flow, upload the matching internal
   build and perform a license-tester purchase lifecycle test.

## 6. Verification

Local verification command:

```powershell
./gradlew.bat :backend:test :app:testDebugUnitTest --no-daemon
```

Required assertions include:

- blank endpoint remains disabled even when the Web client ID is configured;
- configured endpoint plus missing or malformed Web client ID fails before a
  connection opens;
- cleartext and malformed endpoints fail before an ID token is sent;
- missing backend Google Web client ID fails closed;
- unknown, stale, expired, ownership-mismatched, unacknowledged, and
  verification-pending entitlement states do not grant Premium;
- `POST /v1/billing/verify` remains non-granting and does not echo a raw token.

No emulator, APK installation, purchase, Cloud Run deployment, Firestore write,
secret read, KMS operation, or Android Publisher API purchase call is part of
this config-wiring phase.
