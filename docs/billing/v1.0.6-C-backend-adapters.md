# Just Notes v1.0.6-C Backend Adapters

Status: implemented locally on `2026-07-10`; Cloud Run deployment is permitted
only after the verification and review gates below pass.

## Implemented Runtime Adapters

| Concern | Production implementation | Fail-closed behavior |
| --- | --- | --- |
| Secrets | Secret Manager version access with a five-minute in-process cache | Missing, malformed, empty, or invalid-version secrets fail the operation |
| Purchase-token hash | HMAC-SHA-256 with the Secret Manager pepper and recorded pepper/hash versions | Raw token is not returned or persisted |
| Account obfuscation | HMAC-SHA-256 derived from the signed-in Google subject and a separate Secret Manager pepper | Android never receives the pepper |
| Purchase-token encryption | Cloud KMS symmetric encrypt/decrypt | Ciphertext must match the configured CryptoKey and algorithm |
| Entitlements | Firestore `entitlements` collection with transactional monotonic writes | Unknown, owner-mismatched, malformed, or older records do not grant or overwrite newer state |
| Token ownership | Firestore transaction on `subscriptions/{purchaseTokenHash}` | A hash already owned by another Google subject is rejected |
| Play verification | Android Publisher `purchases.subscriptionsv2.get` | API errors and unknown future states are non-granting and token-redacted |
| Acknowledgement | Android Publisher subscription acknowledgement | I/O/429/5xx/409 failures are classified as retryable; no token appears in the result |

Production clients use Application Default Credentials supplied by the Cloud
Run runtime service account. The repository contains no service-account JSON
key, OAuth client secret, Secret Manager payload, KMS key material, raw Google
ID token, or raw purchase token.

Startup validates the OAuth Web client audience together with every Cloud
resource identifier, including Google Cloud project and Firestore database
naming rules. Missing or malformed configuration stops the process, so
`/v1/health` cannot report success for an unusable deployment.
The production artifact contains no in-memory or no-op entitlement repository.

Deterministic HMAC secrets are pinned to numeric Secret Manager versions.
`versions/latest` is rejected by production configuration because advancing the
alias would change existing token hashes and obfuscated account IDs. A future
pepper rotation must use an explicit multi-version migration.

## Firestore Subscription Document

The ownership transaction writes only:

- `purchaseTokenHash`
- `hashVersion`
- `pepperVersion`
- `ownerGoogleSub`
- `packageName`
- `productId`
- `basePlanId`
- `tokenCiphertext`
- `keyVersion`
- `encryptedAt`
- `encryptionAlgorithm`

There is deliberately no `purchaseToken` field.

## HTTP Boundary For v1.0.6-C

The production adapters exist and are wired at process startup, but the
purchase orchestration route is intentionally disabled:

- `POST /v1/billing/verify` authenticates and validates catalog metadata, then
  returns HTTP `202`, `hasPremium=false`, `VerificationPending`, and
  `POST_VERIFY_DISABLED`;
- the route does not call Android Publisher, KMS, acknowledgement, or Firestore
  write operations;
- entitlement reads still require an explicitly backend-verified, acknowledged,
  grantable, unexpired record inside the stale window;
- `POST /v1/play/rtdn` remains HTTP `501`;
- no real purchase or purchase token is processed in v1.0.6-C.

This boundary is covered by a test whose injected Play verifier throws if it
is called. The request still returns the non-granting response.

## Verification And Deployment Gate

Required before Cloud Run deployment:

1. `:backend:test` and `:app:testDebugUnitTest` pass.
2. The standalone Docker image builds from `backend/Dockerfile`.
3. Repository secret scans and `git diff --check` pass.
4. `codex xhigh/review` reports no blocking finding, or every finding is fixed
   and the affected checks are rerun.
5. Only the intentional backend/config/documentation changes are committed and
   pushed.

After the gate passes, deploy `just-notes-entitlement-api-dev` in `asia-east1`
using the existing runtime service account and `backend/cloudrun/dev.env.yaml`.
Record the revision and HTTPS origin here, verify the public health route and
the unauthenticated `401` behavior of protected routes, then wire the origin to
Android and rebuild the debug APK.
