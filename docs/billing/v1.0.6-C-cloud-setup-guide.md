## 1. Executive Summary

v1.0.6-C 是 Console setup guide，不是 deploy guide，也不是 implementation
change。

本階段仍維持：

- 不開 purchase button。
- 不讓 `launchBillingFlow` reachable。
- Android runtime 不呼叫 `POST /v1/billing/verify`。
- `POST /v1/billing/verify` 仍是 non-granting。
- `POST /v1/billing/verify` 不得讓 `hasPremium=true`。
- 不建立 service account key file。
- 不下載 service account JSON key。
- 不把 secret、credential、raw token 放進 repo。

本階段目標是準備 dev backend 需要的設定：

- GCP project / dev environment 決策。
- OAuth Web client ID。
- Android OAuth client fingerprint 檢查。
- Android Publisher API / Play Console API access。
- Cloud Run runtime service account。
- Firestore Native mode database。
- Secret Manager pepper secrets。
- Cloud KMS key for token encryption。

正式 Cloud Run backend 應使用 runtime service account / service identity，也就是
Application Default Credentials (ADC) 路徑。不要用 repo 裡的 key file，也不要把
service account JSON key 放進 Android app。

## 4. Console Step-by-Step: Google Cloud Project

目的：確認 dev backend 要使用哪個 Google Cloud project。

2. 點上方 project selector。
3. 檢查是否已有 Just Notes 用於 Drive sync 的 project。
4. 如果有現有 Just Notes project，確認：
   - project 屬於 Brian。
   - OAuth consent screen 顯示的是 Just Notes。
   - OAuth clients 對應 `com.brianyeh.justnotes`。
   - Brian 同意 dev backend 先 reuse 這個 project。
5. 如果沒有合適 project，建議 dev project 名稱使用 `just-notes-dev`。
6. 本 guide 階段不要由 Agent 建立 project。
7. 不要先啟用 billing、建立資源或部署服務，除非 Brian 明確同意下一步 setup。

請記錄：

- GCP project display name。
- GCP project ID。
- GCP project number。
- 這是 reused existing project 還是 planned new dev project。
- Project selector / project dashboard 截圖。

判斷原則：

- 如果現有 project 本來就是 Just Notes project，且 OAuth / Play API 會比較單純，

## 6. Console Step-by-Step: OAuth Web Client ID

目的：建立或確認 backend Google ID token verifier 的 audience，也就是 Android
`requestIdToken(webClientId)` 要使用的 Web client ID。

操作步驟：

1. 到 Google Cloud Console -> APIs & Services -> Credentials。
2. 檢查是否已有 OAuth 2.0 Client ID，Application type 是 Web application。
3. 如果沒有，建立新的 Web application OAuth client。
4. 名稱建議：`Just Notes Backend Dev Web Client`。
5. 建立或確認後，記錄 Web client ID。
6. 這個 Web client ID 要給 Android `requestIdToken(webClientId)`。
7. Backend verifier 的 `aud` 也要驗這個 Web client ID。
8. 不要把 Web client secret 放進 Android app。
9. 不要把 Web client secret 放進 repo。
10. 不要把 Web client secret 貼到 chat、docs、logs。

請記錄：

- OAuth client 名稱。
- Web client ID，格式通常是 `xxx.apps.googleusercontent.com`。
- 所在 GCP project ID。
- Console 截圖，secret 欄位不要露出。

Android OAuth client 仍需要確認：

- Debug SHA-1 / SHA-256。
- Release upload key SHA-1 / SHA-256。
- Play App Signing SHA-1 / SHA-256。
- Package name 必須是 `com.brianyeh.justnotes`。

重要區分：

- Android OAuth client 用來識別 Android app 和 signing certificate。
- Android `requestIdToken(webClientId)` 使用的是 Web client ID。
- Backend `GOOGLE_WEB_CLIENT_ID` / verifier `aud` 也使用同一個 Web client ID。
- Android OAuth client ID 不應拿來當 backend verifier 的 audience。

- Region: `asia-east1`。

操作步驟：

1. 到 Google Cloud Console -> Firestore。
2. 確認目前 project 是否已經有 Firestore database。
3. 如果已存在，記錄 mode 和 region。
4. 如果尚未建立，先確認 location。Firestore location 建立後不易搬移。
5. Brian 確認後，選 Firestore Native mode。
6. Region 建議選 `asia-east1`。
7. 本 guide 只建立 / 確認 database，不建立 collections，不寫資料。

Future collections plan：

- `users`
- `subscriptions`
- `entitlements`
- `verificationEvents`
- `auditLogs`

請記錄：

- Firestore mode。
- Firestore region。
- Database 是否已存在。
- 是否新建 database。
- Console 截圖。

Fail-closed 要求：

- Unknown 不 grant。
- `VerificationPending` 不 grant。
- `expiryTime <= now` 不 grant。
- 未 ownership verified 不 grant。
- 未 acknowledged 或 backend acknowledge 未成功不 grant。

## 8. Console Step-by-Step: Cloud Run Service Account

目的：建立 future Cloud Run backend 使用的 runtime service account。這個 service
account 是 Cloud Run 的 service identity，不是下載 key 給 app 或 repo 用。

建議 service account：

- Name: `just-notes-entitlement-api-dev-sa`
- 用途：Cloud Run runtime service identity。

操作步驟：

1. 到 Google Cloud Console -> IAM & Admin -> Service Accounts。
2. 選定 dev backend project。
3. 建立 service account：`just-notes-entitlement-api-dev-sa`。
4. Display name 建議：`Just Notes Entitlement API Dev`。
5. 不建立 key。
6. 不下載 JSON key。
7. 不把 key 放 repo。
8. 不把 key 放 Android app。
9. 未來 Cloud Run service 要以這個 service account 作為 service identity。

IAM 最小權限草案：

- Firestore / Datastore document read/write role：只給 backend 需要讀寫文件的權限。
- Secret Manager Secret Accessor：只針對 needed secrets，不要 project-wide 任意擴張。
- Cloud KMS CryptoKey Encrypter/Decrypter：只針對 needed key。
- Android Publisher API 權限由 Play Console API access 管理，不靠 GCP IAM
  owner/editor。

請記錄：

- Service account email。
- Service account unique ID。
- 授權了哪些 IAM roles。
- 每個 role 是 project-level 還是 resource-level。
- Console 截圖。

安全要求：

- 不使用 default compute service account。
- 不使用 owner/editor 當捷徑。
- 不建立 service account key file。
- 不下載 JSON key。

## 9. Console Step-by-Step: Secret Manager

目的：建立 backend-only peppers。這些 secret 只給 Cloud Run runtime service
account 讀取，不給 Android，不進 repo，不進 log。

要建立的 pepper secrets：

- `just-notes-token-hash-pepper-dev`
- `just-notes-obfuscated-account-pepper-dev`
- `just-notes-email-hash-pepper-dev`

操作步驟：

1. 到 Google Cloud Console -> Security -> Secret Manager。
2. 確認在 dev backend project。
3. 建立 `just-notes-token-hash-pepper-dev`。
4. 建立 `just-notes-obfuscated-account-pepper-dev`。
5. 建立 `just-notes-email-hash-pepper-dev`。
6. 每個值都應該是 high entropy random secret。
7. 不要把 secret value 貼到 repo。
8. 不要把 secret value 貼到 log。
9. 不要把 secret value 給 Android。
10. 只授予 Cloud Run service account `Secret Manager Secret Accessor`。

請記錄：

- Secret names。
- Secret versions。
- 哪個 service account 有 accessor 權限。
- Console 截圖，secret value 必須遮住。

安全要求：

- 不重用 OAuth / Drive secret 當 pepper。
- 不把 pepper 寫進 Android source。
- 不把 pepper 寫進 Gradle file。
- 不把 pepper 寫進 example config。
- 之後 backend records 要保留 `hashVersion` / `pepperVersion`。
