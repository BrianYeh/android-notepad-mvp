## Security and grant invariants

- Android never grants Premium from `PendingPurchase` or `ClientObserved` state.
- Only a backend-verified, unexpired, grantable, acknowledged entitlement grants Premium.
- The raw purchase token is transient: it is sent to the authenticated backend, never persisted by Android, never logged, and never stored raw in Firestore.
- The backend checks Google identity, Play truth, catalogue, backend-issued obfuscated account ownership, and unique token ownership before acknowledgement or entitlement grant.
- A retry delay retains only a timer; the next Play query reacquires the token.
- RTDN remains disabled (`501`) on the public Android API. Google Play publishes only to a separate IAM-private Cloud Run RTDN service.

## Rollback conditions

Immediately stop testing, disable the internal release/backend-flow flag, and route Cloud Run back to the captured prior revision if any of these occurs:

- ownership mismatch or first-binder attempt grants;
- acknowledgement failure grants;
- Pending, expired, revoked, or ClientObserved state grants;
- raw purchase token, bearer token, Google subject/email, or ciphertext appears in logs or screenshots;
- Firestore stores a raw token or lacks encryption/key metadata;
- authenticated context, health, or fail-closed auth smoke checks fail;
- the Play-delivered build differs from version code 5 / version name 1.0.7 or enables client-only entitlement.

Rollback command template:

```powershell
gcloud run services update-traffic just-notes-entitlement-api-dev `
  --project gen-lang-client-0599059254 `
  --region asia-east1 `
  --to-revisions "$previousRevision=100"
```

## RTDN deployment status

The public Android API intentionally keeps `/v1/play/rtdn` disabled with 501. The separately deployed `just-notes-rtdn-dev` service is IAM-private and accepts only Pub/Sub OIDC push from `just-notes-rtdn-push-dev`. It deduplicates and leases message IDs, refuses first binding, hashes the untrusted token hint only for owner lookup, decrypts the stored KMS ciphertext, verifies the token/hash match, requeries Android Publisher, and reconciles Firestore monotonically from Play truth rather than trusting lifecycle fields in the notification.

The complete live resource, IAM, retry/dead-letter, Play Console, TTL, canary, leakage, and rollback record is in `docs/billing/v1.0.7-rtdn-runbook.md`.
