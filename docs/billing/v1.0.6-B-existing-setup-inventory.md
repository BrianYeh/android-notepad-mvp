## Reuse Decisions by Category

### 1. Confirmed complete, can directly reuse

- Play package name: `com.brianyeh.justnotes`.
- Play subscription product: `just_notes_premium`.
- Base plans: `monthly`, `annual`.
- Offer: `monthly/trial10d`.
- Annual no-trial rule.
- Taiwan availability / pricing.
- OAuth Web application client: `Just Notes Backend Dev Web Client` in project
  `gen-lang-client-0599059254`, status `Enabled`, created `2026-07-08`.
- Current app purchase restrictions: purchase button hidden and `launchBillingFlow` unreachable.

These should become hard allowlists or guardrails. They do not require new design
work, but implementation still must verify them from Play API responses rather
than trusting client request fields.

### 2. Likely complete, verify in console

- OAuth consent screen.
- Drive API and Drive `appData` scope for Drive sync.
- Android OAuth client for package `com.brianyeh.justnotes`.
- Debug, release upload key, and Play App Signing SHA fingerprints.
- Play internal testers and license testers.
- Play Console API access and service account permission.

These can probably be reused, but they are not all equivalent to backend billing
verification setup. Drive API / appData scope is for Drive sync only. Android
OAuth client identifies the Android app, while backend ID token audience
validation requires a Web client ID.

### 3. Cannot directly reuse; backend entitlement needs new setup

- Cloud Run Admin API was checked on 2026-07-08 and remains intentionally not
  enabled before the reviewed deployment. Firestore and Datastore APIs were
  enabled on 2026-07-09; Secret Manager, Cloud KMS, and Android Publisher APIs
  were enabled on 2026-07-10.
- Cloud Run backend service name and region.
- Cloud Run service deployment configuration (service name, region, invoker
  model, and attaching the already-created runtime identity).
- Firestore entitlement schema and transaction ownership implementation.
- Secret Manager pepper rotation policy (the three initial Secrets and
  resource-level accessor IAM are confirmed complete).
- KMS / Tink token encryption strategy and key versioning.
- Backend access to Android Publisher API through Play Console-linked service identity.
- Audit retention, verificationEvents TTL, log redaction policy, GET reverify TTL, and maxStale.
- Non-granting `POST /v1/billing/verify` gate until v1.0.7.

These should not be silently inferred from Drive sync setup. They need explicit
console verification or new backend-specific decisions before implementation.

### 4. Do not use / unsafe

- Service account key JSON files in repo.
- Service account key JSON files inside Android app.
- Reusing Drive OAuth scope as proof of billing entitlement.
- Android computing backend HMAC pepper values.
- Raw purchase token logs.
- Google ID token logs.
- Raw email / raw `googleSub` logs.
- Any path that grants premium before owner verification, acknowledgement, and
  `expiryTime` checks pass.
